# Architecture, Tech Stack & Coding Standards

This document defines the technical stack and coding conventions for **Gusto '26 (2.0)**. Every AI agent and team member must follow these standards to keep the codebase consistent and error-free.

---

## 🛠️ Core Tech Stack

| Layer | Technology | Version | Notes |
| :--- | :--- | :--- | :--- |
| **Framework** | Next.js (App Router) | `16.3.6` | Uses modern Next.js 16 conventions (see below). |
| **UI Library** | React | `19.2.8` | Server Components by default; React 19 hooks available. |

## ⚠️ Next.js 16 Mandatory Conventions

Next.js 16 introduces breaking changes compared to older Next.js 13/14/15 tutorials. **Always verify in `node_modules/next/dist/docs/` before writing framework code:**

1. **Async Dynamic APIs (`params` & `searchParams`)**:
   - In `page.tsx`, `layout.tsx`, and `generateMetadata`, both `params` and `searchParams` are **Promises** and must be awaited:
     ```tsx
     export default async function EventDetailPage({
       params,
     }: PageProps<"/events/[slug]">) {
       const { slug } = await params;
       // ...
     }
     ```
2. **Global Route Type Helpers (`PageProps` & `LayoutProps`)**:
   - Next.js 16 provides globally available `PageProps<"/route">` and `LayoutProps<"/route">` types (generated by `next dev` / `next typegen`). Use them when typing layouts and pages (as seen in `app/layout.tsx`).
3. **Request Interception (`proxy.ts`)**:
   - If request interception/rewrites are ever needed, Next.js 16 uses `proxy.ts` rather than legacy middleware patterns. Check `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md` first.
4. **Managed `AGENTS.md` Block**:
   - Never delete the `<!-- BEGIN:nextjs-agent-rules --> ... <!-- END:nextjs-agent-rules -->` block in `AGENTS.md`.

## 🎨 Styling & `app/globals.css` Governance (Tailwind CSS v4)

1. **No `tailwind.config.js` Needed**:
   - Tailwind CSS v4 is configured directly inside `app/globals.css` using `@import "tailwindcss";` and `@theme inline { ... }`.
2. **Strict 4-Section Structure in `app/globals.css`**:
   To prevent Git merge conflicts across the 3 team members, `app/globals.css` is strictly divided into 4 sections:
   - **Section 1 (`1. DESIGN TOKENS`)**: `:root` and `@media (prefers-color-scheme: dark)` CSS variables.
   - **Section 2 (`2. TAILWIND V4 THEME MAPPING`)**: `@theme inline` mapping CSS variables to Tailwind utility classes.
   - **Section 3 (`3. BASE ELEMENT DEFAULTS`)**: `html`, `body`, and `::selection` base resets (uses `var(--font-sans)` so `Geist` font from `app/layout.tsx` is properly applied).
   - **Section 4 (`4. SHARED SYMPOSIUM UTILITIES & KEYFRAMES`)**: Reusable global keyframes or utility classes only. **Never put page-specific or component-specific CSS in `app/globals.css`.**
3. **Semantic Theme Tokens Reference**:
   Use these shared Tailwind utility tokens across all components:

   | Token Variable | Tailwind Utility (`bg-*` / `text-*` / `border-*`) | Purpose |
   | :--- | :--- | :--- |
   | `--background` | `bg-background` | Primary page background |
   | `--foreground` | `text-foreground` | Primary body & heading text |
   | `--surface` | `bg-surface` | Card / section container surface |
   | `--surface-elevated` | `bg-surface-elevated` | Hover state / modal / elevated card surface |
   | `--border` | `border-border` | Subtle dividers and card borders |
   | `--muted` | `text-muted` | Secondary / muted captions and labels |
   | `--brand-primary` | `bg-brand-primary`, `text-brand-primary` | Primary symposium brand accent |
   | `--brand-secondary` | `bg-brand-secondary`, `text-brand-secondary` | Secondary gradient / badge accent |
   | `--brand-accent` | `bg-brand-accent`, `text-brand-accent` | Highlight / cyber-cyan accent |

4. **Responsive & Accessible Design**:
   - College symposium traffic is **70%+ mobile** (students opening links from WhatsApp/Instagram). Every page and component must be **mobile-first** (`sm:`, `md:`, `lg:`) with touch-friendly tap targets (`min-h-11`).
   - Maintain high contrast for text over dark/gradient backgrounds and provide semantic HTML (`<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`).
5. **Images**:
   - Use `next/image` with explicit `width`/`height` or `fill` (with `sizes`) for local and remote images to prevent layout shift.

## 🧩 Data-Driven Symposium Architecture

To avoid merge conflicts when updating event rules, timings, or coordinator phone numbers:
- **Never hardcode event lists or schedules inside React components.**
- Define TypeScript interfaces in `types/symposium.ts`.
- Store all symposium content in `data/*.ts`.
- Components in `components/sections/` receive typed props or read from `data/*.ts`.
